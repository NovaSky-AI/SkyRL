SkyRL provides support for end-to-end training with the FSDP and Megatron training backends (both using vLLM for inference),
as well as support for a JAX backend (for both training and inference) via the [Tinker API server](/docs/tinker/overview).

## FSDP
Any model that is supported via HuggingFace transformers + vLLM is supported via the FSDP backend. The FSDP backend also comes with support for Ulysses-style sequence parallelism,
making it a viable option for training on dense models with up to 32B parameters and 32K/64K context lengths.

## Megatron
The [Megatron backend](/docs/examples/megatron) comes with support for 5D parallelism (DP/TP/CP/PP/EP) and allows for efficient scaling of large MoE models (100B+).
Support for mapping from HuggingFace model definitions to Megatron GPTModels is provided by NVIDIA's [Megatron-Bridge](https://github.com/NVIDIA-NeMo/Megatron-Bridge) library.
All of the models in the table above are supported via Megatron-Bridge + vLLM.

Other models supported via [Megatron-Bridge](https://github.com/NVIDIA-NeMo/Megatron-Bridge#supported-models) and vLLM should run on SkyRL as well. Contributions and bug fixes for additional model families are welcome!

## JAX
The JAX backend supports the following models:
- Qwen-3.5 Dense
- Deepseek-V3
- Llama-3
- Qwen3 Dense/MoE

## Known limitations
- Vision-language checkpoints (Kimi K2.x, GLM-5.3) are trained text-only (`language_model_only=true`), the vision tower stays frozen in vLLM. Qwen-3.5 VL is the exception and can train the vision tower.
- MTP heads are dropped by default. Supported models can train them with `trainer.mtp.enabled=true`, see [MTP training and speculative decoding](/docs/examples/spec_decode).
- For FP8/INT4 release checkpoints the Megatron trainer needs a BF16 copy. See the model page for which checkpoint to use.

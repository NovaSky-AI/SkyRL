---
title: "vLLM Engine Metrics"
---

SkyRL routes vLLM engine metrics through Ray's per-node Prometheus agents and
collects aggregate step metrics and weighted run summaries. Collection is on by
default:

```yaml
generator:
  inference_engine:
    enable_ray_prometheus_stats: true
```

Each engine uses vLLM's `RayPrometheusStatLogger`. Ray exposes the metrics at
`http://<node-ip>:<MetricsExportPort>/metrics`. Names replace vLLM's `:` with `_`
and gain the `ray_` prefix. Histograms expose `_sum`, `_count`, and `_bucket`.
Use canonical `_total` counters; adding their legacy aliases counts events twice.

## Step metrics

The collector filters by the WorkerIds of the inference actors SkyRL launches
at setup. That population stays fixed; replacement workers and late joins are
not supported. External deployments without launched actors retain the existing
unfiltered collection behavior.
If launched worker identities cannot be obtained, collection is disabled.

Sync training uses `vllm/train/` and `vllm/eval/`; async training uses `vllm/` for
its combined observed population. Async evaluation can overlap training
rollouts, so its engine counters cannot be attributed separately. Step metrics
are observations between collection boundaries, not exact request-level
attribution; Ray export lag can move counters across step or phase boundaries.

| Suffix | Calculation |
| --- | --- |
| `num_requests_running`, `num_requests_waiting` | Sum of engine gauges |
| `kv_cache_usage_perc` | Mean engine gauge |
| `generation_throughput_tok_s`, `prompt_throughput_tok_s` | Total token delta / active generation seconds |
| `prefix_cache_hit_rate`, `external_prefix_cache_hit_rate` | Hit-token delta / queried-token delta |
| `num_preemptions` | Scheduler preemption-event delta |
| `preemptions_per_million_tokens` | Preemptions × 1e6 / output-token delta |
| `kv_offload_store_throughput_bytes_s`, `kv_offload_load_throughput_bytes_s` | Transferred byte delta / active generation seconds |
| `ttft_seconds_avg`, `request_tpot_seconds_avg` | Merged histogram sum delta / count delta |
| `ttft_seconds_p50`, `ttft_seconds_p90`, `request_tpot_seconds_p50`, `request_tpot_seconds_p90` | Quantiles interpolated from merged cumulative bucket deltas |
| `itl_seconds_avg` | Inter-token latency sum delta / count delta |
| `tpot_seconds_avg` | Compatibility alias for ITL mean |
| `generation_throughput_cv`, `prompt_throughput_cv` | Population standard deviation / mean of per-engine token deltas |

Request TPOT uses `request_time_per_output_token_seconds`; TTFT uses
`time_to_first_token_seconds`. ITL is a separate observation population. Ray's
OpenTelemetry export reconstructs histogram observations from bucket midpoints,
so exported means and percentiles can be estimates. Incompatible engine bucket
schemas are not merged.

Generation duration is the union of outstanding generation calls, including
rollout environment waits. Overlapping async calls count once. The separate
`ray_skyrl_generation_active_calls{run_name="..."}` gauge reports outstanding
calls for timeline correlation; it does not gate counter rates.

CV includes observed idle engines and has a companion `_num_engines` suffix.
It is omitted for fewer than two engines or zero mean. Compare equivalent
engines. Unsupported metrics and zero-denominator ratios are omitted. Fresh
owned engines have known zero counter baselines; other missing values remain
unknown. Unavailable exports retain a baseline for a later complete snapshot,
and decreasing counters invalidate the affected interval.

Prefill/decode deployments still export their raw Ray metrics, but generic
training collection is disabled until role-specific accounting is available.
Both roles can report the same prompts and requests, and prefill can report a
placeholder generated token; summing them does not yield logical run totals.

## Run summaries

W&B receives `vllm_run/train/`, `vllm_run/eval/`, or `vllm_run/combined/` summary
fields. Other configured loggers continue receiving step scalars. A local
`vllm_run_summary.json` is saved under `trainer.ckpt_path` on finalization.

Run throughput uses summed tokens / summed active duration. Cache rates use
summed hits / summed queries; means and percentiles use merged histogram
statistics. Run summaries also include token/preemption/offload-byte totals,
`active_generation_seconds`, `observed_active_seconds`,
`unobserved_active_seconds`, and `incomplete_windows`. The last field counts
unavailable or invalid collection attempts; a later snapshot can recover their
counters and duration. Use unobserved seconds to identify unrecovered coverage.

`run_status` becomes `success` or `failed` on handled exit. Partial summaries
update during logging. Accumulators persist in training checkpoints;
`vllm_run/covers_resumed_history` reports whether restored history is included.
Fresh engines establish new baselines after resumption. Final collection allows
a bounded terminal export drain without adding idle time to generation duration.
A hard kill cannot finalize status or annotations.

In W&B, add run-table columns for status, output tokens, throughput, preemptions
per million tokens, cache hit rates, offload bytes/s, and TTFT/request TPOT.
Compare weighted summary fields rather than averaging step rates.

## Optional Grafana annotations

```yaml
trainer:
  grafana_annotations:
    enabled: true
    url: https://grafana.example.com
    token_env_var: GRAFANA_API_TOKEN
    tags: [training]
    record_directory: ~/skyrl_runs/annotations
```

Set the named token environment variable on the driver. SkyRL forwards it to
its runtime without logging the value. Annotation text is exactly the run name;
a unique invocation ID is stored in tags. A start event becomes a start/end
region on handled finalization. Requests are bounded and failures do not stop
training. Local records preserve annotation ID, timestamps, and status.

In Grafana, enable an organization annotation query with the `skyrl-run` tag.
Regions cover startup through finalization; use the activity gauge to correlate
generation. Optional `organization_id`, `dashboard_url`, and `timeout_seconds`
settings control routing and links. No dashboard JSON is installed by SkyRL.

## Prometheus queries

Merge engine buckets before calculating latency quantiles:

```text
histogram_quantile(
  0.90,
  sum by (le) (rate(ray_vllm_time_to_first_token_seconds_bucket[2m]))
)
```

Scope queries to the intended cluster, model, and engine population. Rolling
Prometheus rates use wall time; W&B run throughput uses active generation time.
For run audits, record exact boundaries and include terminal exports when
checking counters. Short runs may finish before their first scrape, in which
case `increase()` alone cannot recover the initial work. A verified fresh-engine
zero baseline plus final cumulative counters can establish those totals.

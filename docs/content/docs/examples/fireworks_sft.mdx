---
title: "Fireworks SFT"
---

SkyRL can run its native supervised fine-tuning loop on a dedicated Fireworks trainer. Fireworks owns model computation and optimizer state; SkyRL continues to own dataset loading, chat templating, assistant-token masks, batching, evaluation, callbacks, and logging.

The hosted entrypoint runs directly in the driver. It does not initialize Ray or require local GPUs, and it provisions no rollout deployment.

## Install

```bash
uv sync --extra fireworks
export FIREWORKS_API_KEY=<your-key>
```

The API key is read from the environment and is not part of SkyRL's serialized configuration. The Fireworks training SDK currently requires Python 3.12 or 3.13.

## Run

The bounded example script prints the paid-resource plan and exits until `FIREWORKS_RUN_CONFIRMED=1` is set:

```bash
bash examples/train/sft/run_sft_fireworks.sh
```

To launch directly:

```bash
uv run --isolated --extra fireworks \
  -m skyrl.train.entrypoints.main_fireworks_sft \
  strategy=fireworks \
  model.path=Qwen/Qwen3-4B \
  model.lora.rank=8 \
  fireworks.base_model=accounts/fireworks/models/qwen3-4b \
  fireworks.training_shape_id=accounts/fireworks/trainingShapes/<validated-shape> \
  fireworks.trainer_job_id=skyrl-smoke-sft-example-trainer \
  fireworks.max_seq_len=32768 \
  fireworks.trainer_replica_count=1 \
  fireworks.cleanup_on_exit=true \
  train_datasets="['yahma/alpaca-cleaned']" \
  train_dataset_splits="['train[:100]']" \
  max_length=512 \
  num_steps=10 \
  batch_size=4 \
  remove_microbatch_padding=false \
  use_sequence_packing=false \
  enable_ray_gpu_monitor=false \
  hf_save_interval=0
```

`model.path` supplies the Hugging Face tokenizer and chat template. Select the tokenizer revision documented for `fireworks.base_model`; their vocabulary and special-token IDs must match even though the two resource names use different namespaces.

## Data and evaluation

The hosted backend reuses `SFTTrainer`, so it accepts the same inputs as local SFT:

- chat datasets with a `messages` column;
- Alpaca `instruction`/`input`/`output` datasets;
- `last_assistant_message` and `all_assistant_messages` masks;
- multiple weighted training datasets;
- evaluation datasets;
- stateful random, sequential, or custom samplers;
- W&B or console logging;
- callbacks when constructing `FireworksSFTTrainer` through the Python API.

## Checkpoints

Persistent checkpointing and resume are not supported in the initial hosted backend. Fireworks DCP objects are scoped to the dedicated trainer and are deleted with it, while SkyRL requires trainer cleanup to prevent ongoing billing. Configure `ckpt_path=""`, `resume_from=""`, `max_ckpts_to_keep=-1`, and `hf_save_interval=0`.

## Initial limitations

The hosted backend currently supports text-only SFT with one trainer replica and assumes the selected shape contains one accelerator for per-GPU throughput reporting. It rejects:

- VLM examples;
- controller sequence packing;
- microbatch padding removal;
- local torch profiling and Ray GPU monitoring;
- periodic Hugging Face export.

Local `placement`, microbatch offload, and deployment/sampling fields do not control the hosted trainer; the selected Fireworks training shape owns its topology. Fireworks trainer shapes and pricing are account-specific. Check the available shapes and current [Fireworks pricing page](https://fireworks.ai/pricing) before launching paid resources.

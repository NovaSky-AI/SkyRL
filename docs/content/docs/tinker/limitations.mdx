This page documents the features that are not yet wired through the Tinker integration. Everything listed on the [Overview](./overview) as supported is expected to work; if you hit an issue with one of those paths, please [open an issue](https://github.com/NovaSky-AI/SkyRL/issues).

## Current Limitations

### Multi-tenant LoRA: Megatron only

Multi-tenant LoRA training and sampling are supported on the **Megatron** backend with vLLM serving per-tenant adapters by name. See [Multi-tenancy](./multi_tenancy) for the operator contract and SL/RL quickstarts. **FSDP** support is pending, and full-parameter fine-tuning remains single-tenant on both backends — calling `create_model` with `lora_rank=0` while another model exists returns an error.

All adapters registered against one server must share the same `(rank, alpha, train_attn, train_mlp)` signature; mismatched signatures are hard-rejected at `create_model`. `seed` is deliberately excluded — it changes an adapter's initial values, not its shape. `target_modules` is fixed server-side and so is identical across adapters by construction.

### LoRA group flags: `train_unembed`, and Megatron

`train_attn` and `train_mlp` are honoured on the **FSDP** backend, where they narrow PEFT's `"all-linear"` to the attention or MLP projections. The exported adapter records which modules it covers, asserted in `tests/tinker/skyrl_train/test_fsdp_lora_flags.py`.

- **`train_unembed` is not honoured on the skyrl-train backend**. A request with `train_unembed=True` logs a warning, and the model's config is reported back with `train_unembed=False`, since that is what was built. PEFT's `"all-linear"` already excludes the output layer, so there is nothing to narrow; honouring the flag would mean targeting `lm_head` separately, which is architecture-sensitive (tied embeddings). It is a warning rather than an error because the Tinker SDK **defaults `train_unembed` to `True`** — every client sends it, so rejecting would break all of them. Use `--backend jax` for unembedding support.
- **A non-default `train_attn` / `train_mlp` on Megatron is rejected.** Megatron builds its LoRA target list from fixed module names rather than by inspecting the model. Since both default to `True`, this only fires when a narrower adapter was explicitly asked for. Use `trainer.strategy=fsdp`, or name the modules directly in `trainer.policy.model.lora.target_modules`.

At least one of `train_attn` / `train_mlp` must be `True`: an adapter covering no modules would have nothing to train.

**MoE expert projections are not covered on FSDP.** Current `transformers` stores them as fused 3-D `nn.Parameter` tensors (Qwen3-MoE, Mixtral, DeepSeek-V3) rather than `nn.Linear` modules, and PEFT can only adapt the latter, so the MLP group is empty on such a model and narrowing to it raises. Megatron adapts MoE experts directly, with its own grouped-expert handling, but rejects these flags.

### No Prompt Logprobs

The `sample()` API does not yet return prompt logprobs, even when requested. A warning is logged but no error is raised. This may affect scripts that rely on prompt logprobs for KL penalty computation.

### KL Penalty

KL penalty (`kl_penalty_coef > 0`) is not yet supported. This requires prompt logprobs from vLLM (not wired yet) and a way to serve frozen base model logprobs after weight sync. This is disabled by default in cookbook recipes, so it is not a blocker for most workflows.

### RL Loss Functions

Only `cross_entropy` and `importance_sampling` are currently wired through the Tinker data conversion path. SkyRL's `PolicyLossRegistry` contains implementations for PPO (`regular`), `cispo`, and others, but these are not yet validated through the Tinker API.

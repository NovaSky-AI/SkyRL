---
title: "Training Callbacks"
---

Callbacks let you inject custom behaviour at training events -- extra logging,
callback-driven checkpointing or evaluation -- without subclassing the trainer.
The API mirrors `transformers.TrainerCallback`, so the shape is familiar if you
come from HF or Lightning.

<Callout type="info">
The callback API lives in
[`skyrl/train/utils/callbacks.py`](https://github.com/NovaSky-AI/SkyRL/blob/main/skyrl/train/utils/callbacks.py).
A runnable example is under
[`examples/train/callbacks`](https://github.com/NovaSky-AI/SkyRL/tree/main/examples/train/callbacks).
The same API works for the RL trainer -- `RayPPOTrainer` also accepts a
`callbacks=` constructor argument.
</Callout>

## Wiring up a callback

Callbacks are passed to the `SFTTrainer` constructor, so they require a small
custom entrypoint instead of `python -m skyrl.train.main_sft`:

```python
import sys

import ray

from skyrl.train.config.sft_config import (
    SFTConfig,
    build_skyrl_config_for_sft,
    validate_sft_cfg,
)
from skyrl.train.sft_trainer import SFTTrainer
from skyrl.train.utils.utils import initialize_ray


@ray.remote(num_cpus=1)
def sft_entrypoint(cfg, skyrl_cfg):
    trainer = SFTTrainer(cfg, skyrl_cfg=skyrl_cfg, callbacks=[MyCallback()])
    trainer.setup()
    trainer.train()
    trainer.shutdown()


def main():
    cfg = SFTConfig.from_cli_overrides(sys.argv[1:])
    validate_sft_cfg(cfg)
    skyrl_cfg = build_skyrl_config_for_sft(cfg)
    initialize_ray(skyrl_cfg)
    ray.get(sft_entrypoint.remote(cfg, skyrl_cfg))
```

Callbacks can also be registered after construction with
`trainer.add_callback(...)`. See
[`main_sft_with_callbacks.py`](https://github.com/NovaSky-AI/SkyRL/blob/main/examples/train/callbacks/main_sft_with_callbacks.py)
for the full example.

## Writing a callback

Subclass `TrainingCallback` and override the events you care about. Every event
receives the same three arguments: `(trainer, callback_input, control)`.

```python
from skyrl.train.utils.callbacks import TrainingCallback


class LogGradNorm(TrainingCallback):
    def on_step_end(self, trainer, callback_input, control):
        gn = (callback_input.metrics or {}).get("grad_norm")
        if gn is None:
            return
        trainer.tracker.log(
            {"diag/grad_norm": gn},
            step=callback_input.global_step,
            commit=False,
        )
```

### Events

| Event | Fires | Per-event payload |
|-------|-------|-------------------|
| `on_train_start` / `on_train_end` | Once, before the loop begins (after checkpoint resume) / after all final saves and eval | -- |
| `on_epoch_start` / `on_epoch_end` | At each epoch boundary | -- |
| `on_step_start` | Before each training step | `batch` |
| `on_step_end` | After each training step | `batch`, `metrics` |
| `on_eval_start` / `on_eval_end` | Around each evaluation pass | `metrics` (on end) |
| `on_save` | After a checkpoint is written | `ckpt_path` |
| `on_log` | Before metrics are committed to the tracker | `logs` (mutable -- add fields in place) |

Multiple callbacks are invoked in registration order.

### CallbackInput

`callback_input` always carries the loop counters -- `global_step`, `epoch`,
`total_steps`, `steps_per_epoch` -- plus the per-event payload from the table
above (other fields are `None`, so null-check what you use). Anything else --
`tokenizer`, `dispatch`, `tracker`, `cfg` -- is reached through `trainer.*`;
those attributes plus `trainer.global_step` are the stable callback surface.

### TrainingControl

Set `control.should_save` or `control.should_evaluate` to request a checkpoint
or an eval pass; the trainer honors and resets the flags once per step, right
after `on_step_end`. Set them from `on_step_end` (or earlier in the same step)
to take effect on the current step -- setting them from a later event
(`on_eval_end`, `on_save`, `on_log`) applies to the next step instead. This is
the hook for custom save/eval policies, e.g. early evaluation when the loss
plateaus.

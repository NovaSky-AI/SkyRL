## 3. Delete `view`, then rename `viewer` to `view` — **done**

The API-only `view` was the first viewer with its UI taken out from under it:
commit `621894c` added it mounting `skyrl_capture.ui.app`, and `09adcc7`

```

```

that said it shows you the pages were right before the UI moved and are right
again.

`build_view_app` keeps its name -- it is what `--record` starts in-process.

## 4. Separate where captured data goes from where the queue lives — **done**

`CAPTURE_DATA_DIR` held two unlike things: the **queue**, which is scratch and
means nothing once drained, and the **payloads**, which are captured data. The
trajectories were somewhere else again. The grouping was left over from when
the database lived there too.

Payloads now follow the record when one is named:

```
<record-dir>/objects/       captured bodies
<record-dir>/<project>/…    the trajectories
<data-dir>/spool/           the queue, and nothing else
```

`resolve_paths` does it, after the CLI has applied `--record-dir`, and it never
moves an explicit `OBJECT_STORE_URI` -- a deployment that named an S3 bucket
meant it.

**The guess that this might be a deletion was wrong.** The object store is not
a duplicate of the record. Measured on a 13-trajectory run:

```
node       180 objects  141 KB   duplicated in the record
request     90 objects   39 KB   ONLY here
response    90 objects   37 KB   ONLY here
tokens      90 objects  194 KB   ONLY here
```

The record embeds node payloads but deliberately carries no raw HTTP bodies --
`record/server.py` answers `/exchanges/{id}/payload` with nulls and says so.
Deleting the object store would lose three quarters of what is in it.

What *is* redundant is the 141 KB of node payloads, written to the object store
during ingestion and embedded again when the trajectory finalizes. Not worth
chasing: it is the smaller half, and the object copy is what the live control
API serves before the record exists.

## 6. Per-token character offsets, written at capture time — **done**

One integer per token beside the ids, written by `TokenNode.attach_text`, and
returned per block by `/v1/trajectories/{id}/paths` as `token_offsets` and
`token_ids`. Token `i` of a block is `text[offsets[i]:offsets[i+1]]`.

**They are checked rather than assumed.** Each token is decoded alone and the
pieces are compared against the span decode. If they disagree, the TITO commit
is refused rather than storing a mapping that is one character out. Readers
only consume the capture-time representation and never load a tokenizer.

Measured cost, on the same 287-token trajectory:

```
before   21,378 B raw   6,481 B zstd
after    22,612 B raw   7,100 B zstd     +6% raw, +10% compressed
```

`text=false` drops them along with the text, since neither is the shape.

## 7. The token inspector, and the linked ramp — **done**

A block's text is now one span per token when the block carries offsets, and
hovering one says what it is:

```
" or"  ·  #29  ·  id 476  ·  in the loss  ·  logprob -2.6030  ·  p 0.074
```

The ramp is kept and connected rather than removed. It is one column per token
and the text is one span per token, so the two share an index: hovering a token
marks its column, and moving along the ramp marks the token. A dip you cannot
point at is a colour; a token whose confidence you cannot see is just text.

**It is scaled to the block, not to 0..1.** On the absolute ramp 81 of 128
tokens in a real sampled span sat above 0.9 probability and the shading said
nothing. Scaled to the span it runs 0.074..1.000, and the least certain token
-- `' or'` at position 29 -- is visible rather than merely present.

Blocks without offsets render as one run of text, exactly as before, so records
written before item 6 lose nothing.

## 8. Delete the SQL path — **done**

Gone: `db/pool.py`, `db/embedded.py`, both migrations, `asyncpg`, and every
`if state is not None:` branch in fourteen modules. `DATABASE_URL` is no longer
read. `skyrl_capture.db.Database` survives as an alias for the in-memory
handle, so several dozen `db: Database` annotations still read as what they

**It took the worker pool with it**, which the plan did not anticipate.
Ingestion writes into state this process owns, so a spawned child would write
into its own copy -- `--num-workers` is refused, `ingest/pool.py` and its test
are deleted, and `bench/ingest_scale.py` went too, since measuring K ingestion
processes has no subject any more. `orphaned_directories` moved to
`ingest/sharding.py`: the shard count can still change between runs.

Done in the order the plan set, and step 1 earned its place -- pointing the
suite at the memory store first is what found the 410/401 regression before
anything was deleted.

Two things the scripted unwinding broke and the tests caught: `run_export` lost
its body after the branch, so exports sat in `running` for ever; and
`_run_once_locked` lost the loop that reads a batch. Both were restored from
git rather than rewritten.

Verified end to end on the bundled mock, with no database installed: the
recursive example produced **32 calls, 66 nodes, 22 paths, 10 branch points** --
identical to the PostgreSQL run. Startup is **1 second**.

## 9. Collapse the record API into the control API — **done**

`record/server.py` is deleted: 338 lines, twelve routes, all of them a second
implementation of handlers the control plane already had. A record now *fills*
a `CaptureState`, and the control plane's own read routes answer from it.

Three pieces:

- **`record/state.py`** -- `RecordState`, a `CaptureState` hydrated from a
  record. Loading is lazy: the index is enough for a listing, so opening a
  1000-trajectory record reads one file per run rather than one per
  trajectory, and a trajectory's exchanges and nodes arrive when something
  asks.
- **`record/runtime.py`** -- the small part of a `Runtime` a read needs: where
  the state is, what the runs ran against, and the tokenizer override. Nothing
  for writing, so a write route that slipped the guard fails on a missing
  attribute rather than doing something surprising.
- **`build_control_app(runtime, read_only=True)`** -- one middleware refusing
  anything that is not a GET, so a write route added later is refused without
  anyone remembering to.

The differences the two apps had are handled once rather than twice:

| | |
| --- | --- |
| Embedded payloads | `load_view` takes `row["payload"]` when the row carries one, and only fetches a uri otherwise |
| `reward` in a listing | the index keeps it as its own column so a listing can sort; `RecordState` puts it back in `annotations`, where it lives everywhere else |

The later capture-time token-text invariant removed renderer and tokenizer
differences entirely: both live and record readers consume the same stored
text and offsets.

Verified: `view --record` serves the record through the control app, reads
answer, and `POST`/`DELETE` return 405 with a sentence saying why. 324 tests.

## 10. Emit `node_spans` — **done**

A row carries `node_spans` as `[[start, end], ...]`, parallel to `node_ids` and
built in the same loop that flattens the path. A node that contributed no
tokens gets an empty span rather than being skipped, because the two lists
lining up is the whole point.

This was the one open item with a live inaccuracy attached. Both claims that
rested on it now hold from an export alone -- that a branch encodes its turns,
and that the train-once rule is checkable per node -- and the `[UPDATE]` in
`skyrl-integration.md` saying the field did not exist is replaced by one saying
it does. `packed-tree-export.md` loses its dependency: what is left there is
the packing itself.
